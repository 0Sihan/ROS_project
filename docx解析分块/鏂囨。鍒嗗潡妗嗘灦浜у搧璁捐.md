## 1. 分块体系总览

### 1.1 四级分块定义

| 级别 | 名称 | 粒度 | 用途 |
|-----|------|------|------|
| Level-0 | 全书级 | 完整 DocObject | 体例统计、编号连续性、全文重复检测 |
| Level-1 | 章节块 | 一章（H1 或等价标题边界） | D3 语义批次检索、知识错误章节聚合 |
| Level-2 | 段落块 | 一个自然段落 | 字词/标点/数字/英文/参考文献精确检测 |
| Level-3 | 句子级定位 | 一个句子（标点切分） | Level-2 发现问题后的 offset 精确定位 |

Level-3 **不作为独立分块单元存储**，只在 Level-2 命中问题后按需在内存中切分，用于精确 offset 计算。

### 1.2 分块流程

```
DOCX 解析 → DocObject（段落列表 + 元数据）
    │
    ▼
Level-0：全书直接使用 DocObject（无需切分）
    │
    ├─→ Level-1 切分：按 H1 标题边界切分章节块
    │        │
    │        └─→ Level-2 切分：每个自然段落独立为一个块
    │                 │
    │                 └─→ Level-3（按需）：句子切分，内存计算，不存库
    │
    └─→ PRE_WARMING：扫描 DocObject 统计体例频次、断言、NER
```

## 2. 分块元数据结构

### 2.1 Chunk 数据结构（Pydantic）

```python
class ChunkMeta(BaseModel):
    chunk_id: str           # UUID，全局唯一
    level: int              # 0 / 1 / 2
    doc_id: str             # 所属文档
    task_id: str            # 所属任务

    # 位置信息
    chapter_idx: int        # 章节序号（0-based）
    chapter_title: str      # 章节标题（H1 文字）
    para_ids: list[str]     # 本块包含的段落 ID 列表（Level-2 通常只含1个）
    offset_start: int       # 在全书中的字符起始偏移（相对 DocObject.raw_text）
    offset_end: int         # 在全书中的字符结束偏移

    # 内容
    text: str               # 块文本（去除格式标记的纯文本）
    type: ChunkType         # paragraph / table / figure_caption / ref_item / special
    tokens_est: int         # 估算 token 数

    # 上下文（不参与检测，仅供 LLM 理解语境）
    context_prev: str | None   # 前一段落文本（≤200字）
    context_next: str | None   # 后一段落文本（≤200字）

    # 书籍类型相关
    doc_category: str       # 所属书籍类型
    force_d3: bool          # 是否强制送 D3（政治类段落标记）
    skip_d1: bool           # 是否跳过 D1 字词检测（公式段落）
```

### 2.2 ChunkType 枚举

| 值 | 说明 | 检测行为 |
|----|------|---------|
| `paragraph` | 普通正文段落 | 全量检测 |
| `table` | 表格（展开为文本） | D1/D2 检测；D5 不做重复 |
| `figure_caption` | 图注/图标题 | D6 编号检测；D1 检测 |
| `ref_item` | 参考文献条目 | D6 格式检测；D1 跳过 |
| `heading` | 标题（H1/H2/H3） | D1 检测；D5 豁免重复 |
| `formula` | 公式段落 | 跳过 D1 字词检测 |
| `special` | 页眉/页脚/注释 | 仅 D6 检测，其余跳过 |

## 3. Overlap 处理规则

### 3.1 Level-1 章节级 Overlap

相邻章节间保留 **200 字 overlap**：

```
第一章末尾 200 字 ──→ 复制到第二章的 context_prev
第二章开头 200 字 ──→ 复制到第一章的 context_next
```

> Overlap 文本只存入 `context_prev/next`，**不计入 `text` 字段**，不参与检测，不计算 offset，仅供 LLM 理解跨章节语境。

### 3.2 Level-2 段落级 Context

每个段落块携带上下各 1 段作为上下文：

```python
chunk.context_prev = prev_para.text[:200] if prev_para else None
chunk.context_next = next_para.text[:200] if next_para else None
```

### 3.3 超长段落的 Overlap

超长段落切分时（见 §8.2）保留 **200 字 overlap**：

```
超长段落（>2000字）
    ├─ 切分点1：0~2000字（含末尾200字 overlap）
    ├─ 切分点2：1800~3800字（含末尾200字 overlap）
    └─ 切分点3：3600~末尾
```

overlap 段标记 `is_overlap=True`，检测时命中的 Issue offset 需减去 overlap 偏移量，避免重复上报。

## 4. 位置追溯映射

### 4.1 全书字符偏移维护

DocObject 解析完成后，对每个段落维护全书字符偏移：

```python
class ParaMeta(BaseModel):
    para_id: str
    text: str
    offset_start: int   # 相对全书 raw_text 的起始字符位置
    offset_end: int     # 结束字符位置
    chapter_idx: int
    chapter_title: str
    para_idx: int       # 章节内段落序号（0-based）
```

### 4.2 Issue 的 location 字段来源

引擎输出 Issue 时，`location` 字段从 Chunk 元数据反算：

```python
def resolve_location(chunk: ChunkMeta, match_offset: int) -> IssueLocation:
    """
    match_offset: 在 chunk.text 内的字符偏移
    """
    global_offset = chunk.offset_start + match_offset
    # 从 DocObject.para_map 查找 global_offset 落在哪个 para_id
    para = doc_object.find_para_by_offset(global_offset)
    local_offset = global_offset - para.offset_start

    return IssueLocation(
        chapter=para.chapter_idx + 1,           # 1-based
        chapter_title=para.chapter_title,
        paragraph=para.para_idx + 1,            # 1-based
        offset=local_offset
    )
```

### 4.3 Level-3 句子级精确定位（按需）

当 D1/D3 等引擎在 Level-2 级找到问题但需要精确到句子时：

```python
sentences = split_by_punct(chunk.text)  # 按句号/问号/感叹号切分
for sent_idx, (sent_text, sent_offset) in enumerate(sentences):
    if match_start >= sent_offset and match_end <= sent_offset + len(sent_text):
        fine_offset = chunk.offset_start + sent_offset + (match_start - sent_offset)
        break
```

## 5. Token 数估算

### 5.1 估算公式

```python
def estimate_tokens(text: str) -> int:
    """
    中文字符按 1.3 token/字估算（Chinese char ≈ 1.3 tokens for GPT-4/Claude）
    英文单词按 1.3 token/单词估算
    符号/数字按 0.5 token/字符估算
    """
    chinese_chars = len(re.findall(r'[\u4e00-\u9fff]', text))
    english_words = len(text.split()) - chinese_chars // 2  # 粗估
    punct_chars = len(re.findall(r'[^\u4e00-\u9fff\w]', text))

    return int(chinese_chars * 1.3 + english_words * 1.3 + punct_chars * 0.5)
```

### 5.2 超限处理

| Token 估算值 | 处理方式 |
|------------|---------|
| ≤2000 | 直接使用，不拆分 |
| 2001–4000 | 加警告标记 `token_warning=True`，优先送轻量模型 |
| >4000 | 自动按句切分（见 §8.2），强制拆分后再送 LLM |

## 6. 书籍类型差异化分块规则

### 6.1 学术著作 / 学位论文（MVP=Y）

| 结构元素 | 分块规则 |
|---------|---------|
| 正文章节 | 按 H1 标题切分 Level-1 块 |
| 摘要/前言/结语 | 独立 Level-1 块（不合并入相邻章节） |
| 参考文献列表 | 每条 `[序号] 作者...` 独立为一个 Level-2 块，`type=ref_item` |
| 连续列举项（①②③ / 一二三） | 识别为列举后合并为一个 Level-2 块 |
| 脚注 | 与关联正文段合并（脚注文本追加到段落末尾） |

### 6.2 政治 / 党史 / 意识形态类（MVP=Y）

| 规则 | 处理方式 |
|-----|---------|
| 全部段落强制送 D3 | 所有 Level-2 块设 `force_d3=True` |
| 领导人讲话段落 | 识别引号包裹的讲话段落，设 `force_manual_review=True` |
| 历史事件段落 | 识别「年代+事件」模式，提升 D3 检测优先级 |

### 6.3 特殊元素通用规则（MVP=Y）

| 元素 | 分块处理 |
|-----|---------|
| 图注/图标题 | 独立 Level-2 块，`type=figure_caption`，`para_id` 关联图编号 |
| 表格 | 展开为文本行，整体作为一个 Level-2 块，`type=table` |
| 行内代码/公式（LaTeX） | 标记 `skip_d1=True`，跳过字词检测 |
| 公式段落（独占一行，含大量数学符号） | `type=formula`，`skip_d1=True` |

## 7. 分块质量控制

### 7.1 超短段落处理

| 情况 | 处理方式 |
|-----|---------|
| 段落 < 10字 | 合并到上一段（如上一段 type 相同）；无上一段则合并到下一段 |
| 孤立标点行（仅含「——」「……」等） | 归入上一段，不独立成块 |
| 纯空行 | 忽略，不生成块 |

### 7.2 超长段落切分

| 情况 | 处理方式 |
|-----|---------|
| 段落 token > 4000 | 按句子切分，保留 200 字 overlap（见 §3.3） |
| 段落 token 在 2001~4000 | 标记 `token_warning=True`，不强制切分 |
| 单句 token > 4000（极端情况） | 按字符强制切分，记录警告日志 |

### 7.3 切分质量 Log

每次任务分块完成后，输出日志：

```json
{
  "task_id": "xxx",
  "total_chunks_L1": 8,
  "total_chunks_L2": 245,
  "merged_short_paras": 12,
  "split_long_paras": 3,
  "force_d3_chunks": 0,
  "skip_d1_chunks": 5,
  "avg_tokens_L2": 187
}
```

## 8. 数据库设计

### 8.1 五种分块规则存储

规格表中定义了五种裁切方式，统一存入 `chunks` 表（PostgreSQL），通过 `chunk_type` 字段区分：

| 裁切方式 | chunk_type 值 | 说明 |
|---------|-------------|------|
| 章节裁切 | `chapter` | Level-1 块 |
| 段落裁切 | `paragraph` | Level-2 普通段落块 |
| 句子裁切 | `sentence` | Level-3（按需，不持久化，内存计算） |
| 全文保留 | `full_doc` | Level-0，仅1条记录 |
| 图与上下文裁切 | `figure_with_context` | 图注+前后段落合并块 |

### 8.2 chunks 表结构

```sql
CREATE TABLE chunks (
    chunk_id        UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    task_id         TEXT NOT NULL REFERENCES tasks(task_id),
    doc_id          TEXT NOT NULL,
    level           SMALLINT NOT NULL,          -- 0/1/2
    chunk_type      TEXT NOT NULL,              -- 见8.1
    chapter_idx     SMALLINT,
    chapter_title   TEXT,
    para_ids        TEXT[],                     -- 段落 ID 数组
    offset_start    INTEGER NOT NULL,
    offset_end      INTEGER NOT NULL,
    text            TEXT NOT NULL,
    tokens_est      INTEGER,
    type            TEXT NOT NULL,              -- ChunkType 枚举
    force_d3        BOOLEAN DEFAULT FALSE,
    skip_d1         BOOLEAN DEFAULT FALSE,
    force_manual    BOOLEAN DEFAULT FALSE,
    context_prev    TEXT,
    context_next    TEXT,
    created_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_chunks_task_level ON chunks(task_id, level);
CREATE INDEX idx_chunks_task_chapter ON chunks(task_id, chapter_idx);
```

### 8.3 重复存储说明

同一段落在 Level-1 和 Level-2 中均有记录（Level-1 的 `para_ids` 包含多个段落；Level-2 的 `para_ids` 通常只有一个）。存储冗余但便于各 Agent 直接按需查询对应粒度的块，不需要二次切分。

## 9. 验收标准

| 验收项 | 指标 | 标准 |
|-------|------|------|
| Level-1 切分 | 章节数量 | 与 DocObject.chapters 数量一致 |
| Level-2 切分 | 段落数量 | 与 DocObject.paragraphs 数量一致（扣除合并/拆分调整） |
| 位置追溯 | offset 准确性 | Issue.location.offset 对应原文字符正确率 ≥ 99% |
| overlap 处理 | 边界漏检 | Level-2 分块边界用例（见测试文档A第十章）全部命中 |
| 超短段落合并 | 无孤立短块 | Level-2 块中 `len(text) < 10` 的数量 = 0 |
| 超长段落切分 | token 上限 | Level-2 块中 `tokens_est > 4000` 的数量 = 0 |
| Token 估算 | 误差率 | 与 tiktoken 实际计数误差 ≤ 20% |
| 分块性能 | 10万字文档 | 分块完成时间 ≤ 30秒 |
